🐈 NestJS Lab — Helpdesk API с нуля

В Vue Lab backend на NestJS был дан вам готовым: auth, tickets, comments, history, WebSocket-gateway — вы его запускали, но не строили. Этот лаб — тот же Helpdesk-домен (тикеты, роли agent/ customer, live-обновления), только теперь вы собираете backend сами, слой за слоем, и на каждом шагу смотрите, что именно скрывает декоратор @Injectable(), когда вы его пишете не глядя.

Что нужно перед стартом: базовый синтаксис TypeScript (классы, интерфейсы, типы — если это ощущается шатко, сессия 1 TypeScript-лабы закрывает ровно это до начала данного лаба); event loop и async/await из чистого JS-лабы (сессия 5); поверхностное знакомство с декораторами и Prisma по курсу — здесь оно становится глубоким, а не остаётся "я видел, но не понимаю, откуда это берётся".

Домен: Helpdesk — тикеты (open/in_progress/resolved/closed), комментарии, история изменений статуса, роли agent/customer, живые обновления по WebSocket. Тот же самый, что в Vue Lab — специально, чтобы в финале можно было сравнить "фронтенд без бэкенда" и "бэкенд без фронтенда" на одном домене.

Стек: NestJS 10 + TypeScript, Prisma + PostgreSQL 16, class-validator, Passport + JWT, @nestjs/websockets (Socket.IO), Jest + @nestjs/testing. Всё в Docker.

Курс, который вы проходили, показал форму: @Controller(), @Injectable(), пара методов — и всё работает. Но "работает" и "понимаю, почему работает" — разные вещи, и именно второе этот лаб закрывает, на том самом домене, который вы уже видели собранным в Vue Lab.

1. Декораторы и reflect-metadata под капотом #

1.1 Декоратор — это просто функция

В курсе вы писали @Injectable() над классом, не задавая вопроса, что это вообще такое. Ответ прозаичен: декоратор — обычная функция, которую TypeScript вызывает во время выполнения модуля, передав ей класс (или его конструктор) как аргумент. @Injectable() ничего "не подключает" сам по себе — он лишь прикрепляет метаданные к классу через служебную функцию Reflect.defineMetadata(ключ, значение, класс) из пакета reflect-metadata.

1.2 Откуда Nest знает порядок аргументов конструктора

Когда в tsconfig.json включён "emitDecoratorMetadata": true, компилятор TypeScript сам, без единой строчки Nest, записывает в метаданные класса типы параметров конструктора — ключ design:paramtypes. Nest на старте приложения просто читает эту метадату через Reflect.getMetadata('design:paramtypes', TicketsController) и получает массив классов ([TicketsService]) — по нему и строит граф зависимостей.

ПРЯМАЯ ПАРАЛЛЕЛЬ С PHP-ЛАБОЙ Это концептуально то же самое, что вы строили руками в PHP-лабе (сессия 6): DI-контейнер v2 там читал типы параметров конструктора через ReflectionClass::getConstructor()->getParameters() и сам создавал зависимости — autowiring. Nest делает ровно это, только источник информации о типах не PHP Reflection API, а TypeScript-компилятор, записавший её заранее в метаданные класса.

2. Modules и Dependency Injection #

2.1 IoC-контейнер: кто на самом деле создаёт ваши классы

В "наивном" коде вы сами пишете new TicketsService(new PrismaService()). С DI это переворачивается: вы объявляете что вам нужно (в конструкторе), а кто создаёт объект и в каком порядке — решает Nest Injector при старте приложения, обходя граф зависимостей модулей.

2.2 Provider scopes: не все провайдеры — синглтоны молча

ScopeКогда создаётся экземплярРиск
DEFAULTодин на всё приложение (singleton)любое поле экземпляра — общее состояние между всеми запросами всех пользователей одновременно
REQUESTновый на каждый HTTP-запросдороже по памяти/времени; нужен, когда сервис хранит что-то специфичное для запроса (например, текущего пользователя)
TRANSIENTновый при каждом внедренииреже нужен; полезен для сервисов без общего состояния, которые дёшево создавать заново
Зачем это знать заранее: DEFAULT-scope — это ровно тот же singleton-контейнер, что вы строили в PHP-лабе; если по привычке хранить в таком сервисе изменяемое поле (например, currentUserId), оно станет общим для вообще всех запросов сразу — гонка данных между пользователями, а не баг в одном запросе.

3. DTO, Pipes и валидация #

Pipe — это не "ещё одна прослойка ради моды", а прямой ответ на вопрос: тело запроса приходит как сырой JSON без гарантий типов — как убедиться, что status действительно один из четырёх допустимых значений, а не строка "лол", прежде чем это дойдёт до Prisma?

// create-ticket.dto.ts
import { IsString, IsEnum, MinLength } from 'class-validator';

export class CreateTicketDto {
  @IsString()
  @MinLength(5)
  title: string;

  @IsEnum(['open', 'in_progress', 'resolved', 'closed'])
  status: string;
}
ПОД КАПОТОМ Глобальный ValidationPipe делает две разные вещи сразу, и это стоит различать: transform — превращает голый JSON-объект в настоящий экземпляр класса CreateTicketDto (через class-transformer), и только после этого validate — прогоняет декораторы class-validator по этому экземпляру. Если запрос не проходит, Pipe сам бросает BadRequestException — до того, как код контроллера вообще начал выполняться.

5. Guards, JWT и refresh-токены #

5.1 Guard — это не Middleware

Middleware в Express-стиле ничего не знает о контроллере и методе, к которому идёт запрос — только о самом HTTP-запросе. Guard выполняется позже, уже имея доступ к ExecutionContext — то есть знает, какой именно метод контроллера сейчас будет вызван, и какие метаданные (например, из @Roles()) на нём висят.

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const required = this.reflector.get('roles', context.getHandler());
    if (!required) return true;
    const { user } = context.switchToHttp().getRequest();
    return required.includes(user.role);
  }
}
СВЯЗЬ С РАЗДЕЛОМ 1 @Roles('agent') — это кастомный декоратор, который под капотом делает ровно то же самое, что @Injectable(): SetMetadata('roles', ['agent']). Reflector.get() в Guard — это то же чтение метаданных через reflect-metadata, только не Nest сам их читает при старте, а ваш собственный код — на каждый запрос.

5.2 Access + refresh: зачем два токена, а не один

Один долгоживущий JWT — риск: украли токен, он рабочий до истечения. Схема с двумя токенами разводит время жизни: access token живёт минуты (в нём права/роль, его никто не хранит в БД — просто проверяют подпись), refresh token живёт дни и хранится в БД в виде хэша, чтобы его можно было единолично отозвать и чтобы каждое использование можно было ротировать (заменить на новый, старый инвалидировать).

6. WebSocket Gateway #

@WebSocketGateway({ cors: true })
export class TicketsGateway {
  @WebSocketServer() server: Server;

  @SubscribeMessage('joinTicket')
  handleJoin(client: Socket, ticketId: number) {
    client.join(`ticket:${ticketId}`);
  }

  notifyTicketUpdated(ticketId: number, payload: unknown) {
    this.server.to(`ticket:${ticketId}`).emit('ticketUpdated', payload);
  }
}
ЦИКЛИЧЕСКАЯ ЗАВИСИМОСТЬ TicketsService должен вызывать notifyTicketUpdated после обновления в БД — то есть Gateway нужно внедрить в сервис. Но если Gateway, в свою очередь, когда-нибудь тоже попросит сервис в конструктор — получится цикл A→B→A, который Nest Injector не сможет разрешить напрямую. Решение — forwardRef(() => TicketsGateway), отложенная ссылка, разрываемая в момент фактического использования, а не в момент построения графа.

const module = await Test.createTestingModule({

@Injectable()
export class ParseTicketStatusPipe implements PipeTransform {
  transform(value: string) {
    const allowed = ['open', 'in_progress', 'resolved', 'closed'];
    if (!allowed.includes(value)) {
      throw new BadRequestException(`Недопустимый статус: ${value}`);
    }
    return value;
  }
}

@Catch(HttpException)
export class HttpExceptionFilter implements ExceptionFilter {

    const res = host.switchToHttp().getResponse();
    res.status(exception.getStatus()).json({
      error: exception.message,
      timestamp: new Date().toISOString(),

  }
}

Шаг 4.4Refresh-токены и ротация#

Реализуйте POST /auth/refresh: принимает refresh-токен, сверяет его хэш с сохранённым в БД (bcrypt.compare), при совпадении выдаёт новую пару access+refresh и перезаписывает хэш в БД — так, что старый refresh-токен становится бесполезен даже если его перехватили позже.

ЭКСПЕРИМЕНТ Сохраните старый refresh-токен перед его использованием, обновитесь один раз, затем попробуйте использовать тот же старый токен повторно — он должен быть отклонён. Это и есть защита от replay-атаки через ротацию.

Шаг 5.2Эмит из сервиса, forwardRef#
@Injectable()
export class TicketsService {
  constructor(
    private prisma: PrismaService,
    @Inject(forwardRef(() => TicketsGateway))
    private gateway: TicketsGateway,
  ) {}

  async updateStatus(id: number, status: string) {
    const ticket = await this.prisma.ticket.update({ where: { id }, data: { status } });
    this.gateway.notifyTicketUpdated(id, ticket);
    return ticket;
  }
}
Шаг 5.3Auth на handshake#
handleConnection(client: Socket) {
  const token = client.handshake.auth?.token;
  try {
    client.data.user = this.jwtService.verify(token);
  } catch {
    client.disconnect();
  }
}
Зачем: WebSocket-соединение живёт дольше одного HTTP-запроса, поэтому JWT здесь проверяется один раз — в момент подключения, а не на каждое отдельное событие.

Зачем отдельно от unit: unit-тест шага 6.1 проверяет логику сервиса в изоляции; e2e поднимает реальное Nest-приложение целиком (модули, Pipes, Guards) и проверяет, что весь HTTP-слой действительно работает вместе, а не только по отдельности.

9. Чек-лист концепций #

  • Декоратор — функция, вызванная при определении класса; сама по себе ничего не связывает.
  • emitDecoratorMetadata + reflect-metadata — то, откуда Nest реально знает типы параметров конструктора.
  • Provider scopes — DEFAULT/REQUEST/TRANSIENT и риск общего состояния в singleton.
  • useFactory/useValue/useClass — три способа подменить, что стоит за токеном провайдера.
  • ValidationPipe: transform (class-transformer) и validate (class-validator) — два разных шага.
  • Guard vs Middleware — доступ к ExecutionContext и метаданным хендлера.
  • Access vs refresh токен — зачем два, а не один, и что такое ротация.
  • forwardRef — как разрывается циклическая зависимость между сервисом и Gateway.
  • Test.createTestingModule — тот же Injector, что и в реальном приложении, с подменой одного провайдера.

10. Глоссарий терминов #

Provider — любой класс, помеченный @Injectable(), который Nest может создать и подставить в конструктор другого класса.

Module — группа связанных provider'ов и controller'ов с явно объявленными экспортами для других модулей.

Scope — правило, как часто создаётся новый экземпляр provider'а (DEFAULT/ REQUEST/TRANSIENT).

Pipe — трансформация и/или валидация входных данных до того, как они попадут в тело метода контроллера.

Guard — проверка "можно ли выполнить этот конкретный обработчик", с доступом к метаданным хендлера.

Interceptor — код, оборачивающий вызов обработчика до и после (логирование, трансформация ответа).

Exception filter — единая точка форматирования ошибок API.

Reflector — сервис Nest для чтения метаданных, записанных SetMetadata/кастомными декораторами.

forwardRef — отложенная ссылка на класс, разрывающая циклическую зависимость при построении графа DI.

Gateway — класс, оборачивающий WebSocket-сервер в тот же модуль/DI-стиль, что и HTTP-контроллеры.
